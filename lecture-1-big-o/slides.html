What happens when the list gets big?

Big-O describes how the work (and the memory) grows as the input grows. We count it, live, in Python.

Ask chat: "If the list doubles to 2,000,000, how many looks for each?" → linear 2,000,000, binary 21. That question is Big-O.

Big-O measures growth, not seconds

  • Time complexity: as the input grows, how much more work?
  • Space complexity: as the input grows, how much more extra memory?
  • n = the size of the input (how many items)
  • We plan for the worst case: the item is last, or not there
  • Same answer on any laptop, in any language

The question: "If my input doubles, how much more work?"

Say: "Big-O does not say 3 seconds. A fast laptop and a slow laptop give different seconds. Big-O describes the shape: double the input, what happens to the work?"

input doubles…work…Big-O
10 → 20stays the sameO(1)
10 → 20goes up by one stepO(log n)
10 → 20doublesO(n)
10 → 20four timesO(n²)

Count the steps: O(1) and O(n) growth.py

** CODE ALONG, about 5 minutes. ** Students: a new file growth.py.

TYPE THIS, in order

growth.py · part 1

def get_first(items):
    return items[0]

growth.py · part 2 (leave one blank line, two in a real file)

def linear_search(items, target):
    steps = 0
    for item in items:
        steps += 1
        if item == target:
            return steps
    return steps

growth.py · part 3

for n in [10, 100, 1000]:
    items = list(range(n))
    print(n, linear_search(items, n))

Ctrl+S, then in the terminal:

python3 growth.py
  • get_first: one lookup, whether the list has 10 items or 10 million → O(1).
  • steps is our counter: +1 every time the loop looks at an item.
  • Say: "range(n) stops at n − 1, so n is never in the list. That is the worst case: we look at everything."
  • Output: 10 10, 100 100, 1000 1000. Steps = n → O(n).
  • Ask: "Change the target to 0. How many steps?" → always 1 (best case). "Big-O plans for the worst case."

A loop inside a loop: O(n²) pairs.py

** CODE ALONG, about 3 minutes. ** New file pairs.py.

TYPE THIS, in order

pairs.py · part 1

def count_pairs(items):
    steps = 0
    for a in items:
        for b in items:
            steps += 1
    return steps

pairs.py · part 2

for n in [10, 100, 1000]:
    items = list(range(n))
    print(n, count_pairs(items))

Ctrl+S, then:

python3 pairs.py
  • Output: 10 100, 100 10000, 1000 1000000.
  • Say: "For every item, we loop over every item again: n × n = n²."
  • Ask: "10 times more items: how much more work?" → 100 times.

Cut it in half every time: O(log n) halving.py

** CODE ALONG, about 3 minutes. ** New file halving.py. The binary search from the binary search lecture, plus a counter.

TYPE THIS, in order

halving.py · part 1

def binary_search(items, target):
    steps = 0
    left, right = 0, len(items) - 1
    while left <= right:
        steps += 1
        mid = (left + right) // 2
        if items[mid] == target:
            return steps
        elif target < items[mid]:
            right = mid - 1
        else:
            left = mid + 1
    return steps

halving.py · part 2

for n in [10, 100, 1000, 1000000]:
    items = list(range(n))
    print(n, binary_search(items, n))

Ctrl+S, then:

python3 halving.py
  • Output: 10 4, 100 7, 1000 10, 1000000 20.
  • Say: "1,000 times more items, and only 10 more steps. Each step throws away half."
  • // = whole-number division (rounds down). range(n) is already sorted.

log n = how many times you can halve n

8 → 4 → 2 → 1
3 halvings: log₂ 8 = 3
nhalvings to reach 1
1,000about 10
1,000,000about 20
1,000,000,000about 30

A thousand times more data adds only about 10 steps.

Say: "A logarithm answers one question: how many times can I cut this in half before I reach 1?"

That's why our halving.py said 10 for 1,000 and 20 for a million. It also shows up in space: a recursive function that halves each time stacks about log n calls.

Four rules for reading Big-O from code

1. Drop the constants

for x in items: ...
for x in items: ...

2n steps → O(n)

2. A fixed loop is O(1)

for x in items:
    for k in range(3): ...

3n steps → O(n)

3. Two inputs, two letters

for s in students:
    for a in assignments: ...

n × m → O(n · m)

4. Plan for the worst case

for x in items:
    if x == target: return True

Could stop early, but → O(n)

Loops one after another add. Loops inside loops multiply.

About 3 minutes. These four come up in the homework snippets.

rulesay
1"Two loops in a row = 2n. Big-O drops the 2: double the input, still double the work."
2"range(3) never grows. Only loops over the input count."
3"Two different lists: give each its own letter. It's only n² when both loops go over the same list."
4"An early return helps when you're lucky. Big-O assumes you're not."

Space: same loop, different memory

def linear_search(items, target):
    for item in items:
        if item == target:
            return True
    return False

Time O(n) · Space O(1): a few variables, no new list

def double_values(items):
    doubled = []
    for item in items:
        doubled.append(item * 2)
    return doubled

Time O(n) · Space O(n): doubled grows with the input

  • Count only extra memory: the list you were given doesn't count
  • Look for new lists, dicts, sets, stored pairs, and recursive calls (each waits on the call stack)

Time and space are two separate answers. They often differ.

Say: "Both loop once, so both are O(n) time. Only the right one builds a list as big as the input."

Our count_pairs was O(n²) time but O(1) space: it only kept a counter. If it stored every pair in a list, space would be O(n²) too.

Branching: O(2ⁿ), and every ordering: O(n!) branching.py

** CODE ALONG, about 4 minutes. ** New file branching.py.

TYPE THIS, in order

branching.py · part 1

import math

calls = 0


def fib(n):
    global calls
    calls += 1
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

branching.py · part 2

for n in [10, 20, 25]:
    calls = 0
    fib(n)
    print(n, calls)

branching.py · part 3

for n in [3, 5, 10]:
    print(n, math.factorial(n))

Ctrl+S, then:

python3 branching.py
  • Say: "global calls lets the function change the counter outside it."
  • Output: 10 177, 20 21891, 25 242785. Each call makes two more calls → about 2ⁿ. Space is only O(n): the call stack holds one path at a time.
  • Then 3 6, 5 120, 10 3628800: the number of orderings of n items is n! (3 × 2 × 1). Trying every ordering = O(n!).
  • O(n log n) without code: good sorting, like Python's sorted(). Split in half (log n levels), touch every item at each level (n).
  • Don't try fib(40) live: over 300 million calls.

Cheat sheet: what to look for

In the codeTimeUsual space
Direct access: items[0], a dict keyO(1)O(1)
A loop that halvesO(log n)O(1)
One loop over the inputO(n)O(1), or O(n) if it builds a list
Halving + touching every item (good sorting)O(n log n)depends
A loop inside a loop, same inputO(n²)O(1), or O(n²) if it stores pairs
Loops over two different inputsO(n · m)depends
A function that calls itself twiceO(2ⁿ)O(n) call stack
Every ordering of the itemsO(n!)O(n!) if stored
